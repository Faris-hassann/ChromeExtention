# Local Browser Agent backend

Express/WebSocket companion for the MV3 extension. Task state, observations, files, model responses, and extracted data exist only in memory and are cleared when tasks end; there is no database.

```powershell
npm install
npm run dev
```

The server binds to `127.0.0.1:3333`. It loads `backend/.env` automatically; externally supplied environment variables take precedence. Add `OPENROUTER_API_KEY` there, then restart the backend. With `LLM_PROVIDER=openrouter`, decisions use `OPENROUTER_MODEL=openrouter/free` by default and fall back to local `qwen2.5:7b` on errors. Without a key, Ollama is used immediately. Set `LLM_PROVIDER=ollama` for local-only decisions. Only `openrouter/free` and explicit `:free` model IDs are accepted.

OpenRouter receives the task and compact page context. API keys stay in the backend and are not exposed by health/settings endpoints. Captured answers stay in temporary task memory and are pasted verbatim through `capture_text` / `paste_text`, rather than regenerated by the model. Captures over 32 KiB fail explicitly.

Check `GET /health` and `GET /api/settings/runtime` for provider configuration and Ollama fallback availability. Reload the unpacked extension at `chrome://extensions` after rebuilding `frontend/dist`; the panel checks its build version against the worker and blocks tasks if they differ.

OpenRouter has one 20-second deadline covering queueing, availability checks, model discovery and inference, with a 512-token output budget and latency-oriented routing. Cloud decisions are serialized per API key. The configured free model is first, followed by up to two catalog models with zero prompt/completion prices and support for tools and required tool choice. The catalog is cached for five minutes; catalog failures leave the configured model usable. Parameter-compatible provider routing handles upstream failover. Paid model IDs are rejected.

`GET /api/providers/openrouter/status` checks the key and free daily quota, caches checks for 60 seconds and shares simultaneous checks. Use `?refresh=true` to refresh explicitly. Status includes credential validity, availability, quota when supplied, a safe reason, checked time and next retry time. Missing counters or failed checks mean unknown availability; they do not falsely mark quota as exhausted. Available quota is not proof of a successful inference.

Exhausted daily quota prevents inference until the next UTC midnight or a refreshed check reports remaining requests. Transient failures use a cooldown (normally 60 seconds; authentication/credit restrictions use five minutes). Retry-After and rate-limit reset hints are respected even when longer than five minutes. Qwen runs during these holds. The panel shows the quota and reset time in your local timezone, provides Refresh OpenRouter status, and distinguishes account limits from upstream capacity, credentials, credit restrictions, timeouts and invalid tool output. Raw error bodies and account identifiers are never displayed. Successful cloud inference must be tested when quota is available; changing models cannot bypass an account quota.

Local Qwen uses compact context and native tool calls with a 90-second total deadline, a 60-second first attempt and at most one retry within the remaining budget. The model stays loaded for 10 minutes. Simple exact Process Name clicks use browser follow-up actions after model discovery, avoiding two extra model requests; richer requests still use model planning. These limits reduce waiting and repeated requests; CPU inference can still be slow.

The panel displays provider progress every five seconds while waiting, action results and visible changes after fresh observations. A successful click is distinguished from a verified page change. Expand or copy Diagnostics for structured, timestamped events. Timing metrics include prompt evaluation without retaining prompts. Configure request budgets in `.env` and restart the backend after changing them.

Redacted JSONL diagnostics are written to `backend/logs/backend.jsonl`, rotated at 5 MiB, and limited to five files. Console verbosity follows `LOG_LEVEL`; file diagnostics retain every level. Page text, screenshots, form values, credentials, cookies, and tokens are not written to diagnostics.
